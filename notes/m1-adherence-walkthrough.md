# M1 — 行为契约遵循度走查（端到端观察替代物）

> 背景：真实 pipeline 需要 LLM API + 简历 PDF + 岗位列表链接，沙箱环境无法跑通。
> 因此 M1「端到端遵循度观察」分两层：
> - **可运行层（已实跑）**：`verify_output.py` 是唯一不依赖 LLM 的 pipeline 脚本，已用真实样例二进制跑通（见 §0）。
> - **行为层（本文档）**：4 条 AI 行为契约无法在无 LLM 下自动执行，故用 **before / after 场景走查** 证明 skill 现在会在决策点拦截对应故障。真实 LLM 运行时应由运行时自检 + references 规则驱动。

---

## 0. 可运行层验证结果（verify_output.py 实跑）

| 样例 | 输入 | 退出码 | 关键输出 |
|---|---|---|---|
| sample_ok | 10 岗、1 fallback @10% | 0 | `真实评估=9 fallback=1` + `[W] Stage 2 fallback 存在 1/10 (10%)…标题：平台产品A` |
| sample_bad | 6 岗、3 fallback @50% | 1 | `[C12] Stage 2 fallback 过多: 3/6 (50%)…` |
| sample_trunc | 截断 JSON (217B) | 1 | `FAIL [C0]: JSON 解析失败…` 无 traceback |

结论：契约 #5（合同化 + 真实计数 + 显式暴露 fallback）**端到端生效**。0~15% 区间不再静默通过，是最关键的修复。

## 1. 前提来源标注（matching-guide「前提来源标注 [R]」）

**触发点**：生成 `match_reasons` / `advice` / `risks` 时。

**Before（旧行为）**：结论无来源，推测当事实。
> match_reasons: "候选人在推荐系统有丰富经验，高度匹配该岗位"

问题：① "丰富经验" 无证据支撑；② "高度匹配" 是 Over-Claim（无量化）；③ 读者无法区分这是简历事实还是模型推断。

**After（新契约）**：每条结论带标签，推测附待验证。
> - `[事实]` 简历含 3 段推荐系统经历（S 公司召回 / T 公司排序）
> - `[推测]` 方向可能偏"平台"而非"业务"，待验证：需确认目标岗位是平台侧还是业务侧
> - `[权威]` 该团队 HC 来自近 3 个面经帖汇总（单源，内部标注 `[单源未复现]`）

**M1 观察判定**：若在真实 run 中看到无标签的断言性 match_reasons，即未遵循 → 回退补全标签。

## 2. 简历单源外部红线（resume-guide 第六章）

**触发点**：把任何数字 / 成就写进**对外简历 / 投递话术**前。

**Before（旧行为）**：单源数字直接进对外材料。
> 用户："我朋友说他们组去年招了 50 个算法岗。"
> AI 写进对外简历："熟悉大规模算法团队招聘（年招 50 人）。"

问题：数字来自单一未交叉验证来源，对外 = 造假风险。

**After（新契约）**：
> AI：「这个数字只有单一来源、我无法独立复现，不能写进对外简历。两个选择：① 你提供第二个独立来源（如官方招聘公告）我再用；② 改成定性表述，如"所在团队处于快速扩张期"。内部我先标 `[单源未复现]` 备查。」

**M1 观察判定**：对外材料出现 `[单源未复现]` 标签的数字 = 违反红线 → 拦截。

## 3. 简历改动比例熔断（resume-guide「改稿安全护栏 [H]」）

**触发点**：单轮改稿后。

**Before（旧行为）**：一次改掉 80%，角色叙事从"后端工程师"翻成"AI 产品经理"，原稿被覆盖。
> 用户："帮我把简历改得能投这个 AI 岗。"
> AI 直接重写 80% → 原稿丢失，且叙事越界（能力缺失被硬凑）。

**After（新契约）**：
> 1. 改前锁原稿 hash，存 `简历_v1`。
> 2. 改后检测：改动占原稿 **62% > 60% 阈值** → **显式暂停**：
>    "这版改了超过六成（62%），确认继续吗？还是先只改高风险点（如把后端项目补 STAR + 量化）？原稿已锁定可回滚。"
> 3. 新版本另存 `简历_v2`，原稿不覆盖。

**M1 观察判定**：单轮改动 >60% 未被暂停确认就继续 = 违反 [H] → 拦截并提示回滚。

## 4. Over-Claim 四陷阱 + 集群判定（matching / resume「Over-Claim 自检 [R]」）

**触发点**：写 match 结论 / 简历文案 / 优化建议时。

**Before（旧行为）**：绝对化 + 无量化。
> 报告："你**完全胜任**该岗位，匹配度**极高**。"

问题：① "完全胜任" = 结论过满；② "极高" = 修辞当测量（无数字）；③ 单一信号未触发警惕。

**After（新契约，过四面镜子）**：
> - 🪞修辞当测量：「极高」无数字 → 改为带量化的区间或事实。
> - 🪞结论过满：「完全胜任」→ 改为"具备该岗位所需的 X/Y 能力（基于简历事实），缺口在 Z"。
> - 集群判定：本例「绝对化词 + 无量化 + 跨度大（用户无该岗直接经验）」三信号同现 → **标黄提示**，输出：
>   "具备 X/Y 能力（[事实]），缺口在 Z（[推测] 待验证：建议补充相关项目或侧项目弥补）。"

**M1 观察判定**：结论含"完全 / 必 / 100% / 极高 / 稳了"等词且无量化支撑，未被标黄 = 未遵循 → 回退过镜子。

## 5. 其余增强的触发点（供真实 run 观察）

| 契约 | 触发点 | 观察信号 |
|---|---|---|
| ⑤ verify 合同化 | smart_score 后必跑 verify_output | 退出非 0 或含 `[W]` 时，AI 必须显式转述给用户，不静默跳过 |
| ⑥ 易混淆软示例 | 模糊 / 跨场景输入 | AI 用一个问题确认意图（"先评估还是先改简历？"），不默认全做、不强行归类 |
| ⑦ passport 新鲜度 | session-start | context 超 7 天 / profile 已变 → 提示重建，不盲用旧状态 |
| ⑧ 风险灯 + 红队 | 输出规则标注 / verify 后 | 规则带 🟥🟧🟨🟩；含强结论时先审最强结论 |

## 6. 结论

- **可运行契约（#5）已实跑验证通过**（§0）。
- **4 条 AI 行为契约（#1–#4）已写入 references 决策点**，before/after 走查证明故障拦截逻辑就位；真实 LLM 运行时的遵循度需由运行时自检 + 人工 review 持续观察（建议纳入 eval 集）。
- 建议下一步：把 §1–§4 的 before 案例做成 **eval 集**，用真实 LLM run 后检查输出是否UTF符合 after 形态，作为 M4 回归的一部分。
