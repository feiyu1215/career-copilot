# 能力模式（自然语言触发，非命令）

> 本文件从 SKILL.md 拆出，按需加载。触发时机：用户意图涉及对齐/规划/调研/研判/交接时读取。

本 skill 是**单 skill、靠理解意图路由**，不引入显式 `/命令`（会钝化灵活性）。下列 5 个「模式」是**内部能力**，由自然语言触发；有副作用的（写档案 / 发投递）需用户确认。对应 Matt Pocock skills 体系的 grill / to-spec / research / thinking / handoff 思想。

## ① 对齐模式（grill / deep-grill 哲学） — 目标模糊时

- 触发：「不知道从哪开始」「帮我规划」「这方向我还没想清楚」「我适合什么方向」
- 核心：**Agent 先调查、再反驳自己、最后只把真正主观的分歧打包问你**（deep-grill 哲学）——不把能自查的问题抛给你当调查员。
- 流程：
  1. **读 context**（`career-context.md`「已决策 / 待决策」）→ 区分哪些疑问是*可自查*的（市场 / 公司 / 岗位要求 / 迁移可行性），转交 **③ 调研模式** / **④ 研判模式** 自己查，**不开口问你**；
  2. **自我反驳**：对每条暂定建议，先提出反驳它的最强理由；扛不住就修正，改不动才标记为真正主观；
  3. **批量升级**：只把"取决于你目标 / 品味 / 风险偏好"或"合理调查后仍拿不到"的分歧，**一次性打包**给你，每条附推荐答案与理由，**确认前不进入实现**；
  4. 关键结论写入 `references/decision-log.template.md` 并同步 `career-context.md`「已决策」。
- **Socratic 兜底（一次一问）**：若你回复暴露"连自己偏好都不清"（如「我也不知道想要啥」），切回一次一问的苏格拉底式追问帮你把偏好问出来，再回到步骤 1。
- 预算与诚实：不强制追问超过必要轮数（见 SKILL.md「纯推理 Stop Conditions」）；自查未覆盖的部分**必须显式披露，绝不静默跳过**（呼应红线「不确定时必须说」）。

## ② 规划模式（spec + tickets） — 目标已大致清晰

- 触发：「帮我规划接下来一个月」「把求职拆成步骤」
- 流程：目标 → 生成「求职 spec」（目标岗位 / 时间线 / 必需材料 / 成功标准，模板见 `references/job-search-spec.md`）→ 拆成周度 tickets → 存 `career-plan.md`，关键待办同步 `career-context.md`

## ③ 调研模式（research） — 需了解公司 / 岗位

- 触发：「调研下 A 公司 AI 岗」「这个团队做什么的」
- 流程：拉公开信息（web_search）→ 输出带引用的 markdown（业务 / 岗位 / 面试官画像），参考 `references/company-research.md`

## ④ 研判模式（thinking） — 复杂抉择

- 触发：「offer A 和 B 怎么选」「国企还是大厂」
- 流程：结构化多视角推理（事实 / 风险 / 个人偏好）；**跨运行时**：在 WorkBuddy 侧可显式调用 comprehensive-thinking 做深度研判，OpenClaw 侧用内置推理 + 输出带理由的结论

## ⑤ 交接模式（handoff） — 会话结束自动

- 流程：见 `references/session-lifecycle.md` session-end，将 `career-context.md` 更新为**结构化交接单**（状态 / 已决策 / 待决策 / 下一步）

## 不应触发（负向边界）

这些输入本 skill 不接管：
- 单纯写代码（非求职相关）、非求职文档写作、投递操作（只分析不代投）、薪资谈判话术、与求职无关的日常闲聊 / 写诗。
- 若用户说「帮我写首诗」「今天天气」等，明确不触发，建议用户用其他工具。
