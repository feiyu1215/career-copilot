# Career Context — 轻量当前状态（会话第 1 步必读）

> 这是"冰箱便利贴"，不是完整档案。目标 **≤200 tokens**，让 AI 在 1 秒内知道"你在哪、在干嘛"。
> 完整经历与历史细节在 `career-profile.md`；事件流在职业日志 JSONL（由 `scripts/career_log.py` 写入）。
>
> **维护规则（结构化交接单）**：
> - session-end 必填四块：状态 / 已决策 / 待决策 / 下一步（见下方字段模板）。
> - 保留焦点公司与关键截止日——这是跨会话最容易丢、最影响决策的信息。
> - 只放"即时有用的状态"，不放长篇经历；决策类进「已决策」，悬而未决进「待决策」。
>
> **隐私约束（同 SKILL.md 红线）**：禁止写入具体薪资数字、面试官真名、身份证号、完整 JD 原文。

---

## 字段模板（结构化交接单，直接复制填空）

> session-end 必填「状态 / 已决策 / 待决策 / 下一步」，确保下一会话无缝接手。

```markdown
# 当前求职上下文（交接单）

## 状态
- 当前阶段: [匹配期 / 面试期 / 规划期 / 空窗期]
- 焦点公司:
  - [公司A] — [三面待通知 / 已拿offer / 准备中 / 已拒]
  - [公司B] — [...]
- 关键截止: [如 "6月15日前决定 offer" / "无"]

## 已决策
- [对齐模式产出的关键结论，如 "方向定大厂后端，暂停国企"]
- [规划模式确定的优先级，如 "本周主攻 A 终面"]

## 待决策
- [悬而未决、需用户拍板的点，如 "是否接受 B 保底 offer"]

## 下一步
- [1-3 件具体动作，如 "准备C技术面 / 跟进A三面结果"]
- 上次匹配 top3: [岗位名-公司，便于直接续接]

## 备注
- [其他跨会话有用信息，如 "用户在纠结国企 vs 大厂"]
```

---

## 初始化（首次无此文件时）

1. 读取 `career-profile.md` 提取：当前阶段、在谈公司、最近一次动作。
2. 按上面模板生成 `career-context.md`，写入 `~/.catpaw/career-copilot/`。
3. 若 `career-profile.md` 也不存在，先走 onboarding 流程建立档案，再回头填 context。

## 更新（session-end 强制）

按结构化交接单四块更新（见字段模板）：
- 匹配完成 → 更新「状态.阶段 / 下一步 / 上次匹配 top3」
- 面试记录 → 更新「状态.焦点公司 / 下一步」
- 简历修改 → 更新「状态.上次操作」
- 收到 offer / 拒信 → 更新「状态.焦点公司 / 状态.阶段」
- 对齐结论（对齐模式产出）→ 写入「已决策」+ 同步 `references/decision-log.template.md`
- 新疑虑 / 悬而未决 → 写入「待决策」
